# 公文审签隔离夹具（#172、#215）

从仓库根目录执行，使用已具备项目测试依赖的 Python。没有依赖请先报告，不需要站点地址、已有账号或模型密钥。

```sh
python -m pytest -q tests/demo_http/test_document_review_flow.py
node --test tests/demo_http/review-transport.test.cjs
```

- **准备**：每个用例新建本地实例、成员和领导的独立身份。用例通过实际登录和应用 HTTP 路由操作临时数据库，不监听端口。语言检查和引用原文用桩；正文、版本、核查规则、权限、审批和审计走实际实现。
- **制造待审件**：`pending_document` 以成员身份生成“【隔离演示】材料核验”稿，先验证缺项会被拦截，再手工补齐文号、主送、发文机关、日期并保存、添加段落批注、经专用送审接口送给领导。需要调试待审现场时，在 `test_review_cycle` 拿到该夹具后暂停：此刻文稿已送审，尚未决定。
- **验收**：领导在收件箱按待审 ID 和标题找到文稿，核对虚拟原文摘录、引用及批注。退回后成员改正文重送，领导同意新版，检查定稿锁定、待办移出、两条已办和四条带操作者及审签单 ID 的审计。另测空箱、文号告警、自送和自审。这里的“虚拟原文”不是对真实政策的核验。
- **清理**：夹具退出（包括断言失败）即释放 TestClient 并删除自己新建的临时业务数据库目录；不写部署库，不调用 reset。再次执行会创建全新的待审件。

**浏览器与截图**（需要允许回环监听、可启动 Chromium 的隔离机器）：

```sh
env -i HOME="$HOME" PATH="$PATH" python -m pytest -q tests/demo_http/test_document_review_ui.py
```

此用例使用现有 `demo-http` 回环夹具的随机测试口令，成员和领导在两个隔离浏览器上下文中操作。1440、1280 两档分别验证确认按钮未被遮挡、取消不发请求、422 原因可读、就地编辑、成功回执与领导收件箱。两张 `确认送审-宽度.png` 留在本次 pytest 的各自 `tmp_path`，不上传。回环服务在用例模块结束时关闭；其临时目录和截图按 pytest 原有保留策略轮换，不要对已有目录使用 `--basetemp`，也不要点站点的重置。
