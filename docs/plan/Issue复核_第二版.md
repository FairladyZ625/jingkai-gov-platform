# Issue 复核（第二版，2026-11-18）

范围：#2–#51（T01–T50）。目标是让任一 Codex worker 或人类开发者领到 Issue 后，一天内、一个 PR 能交付，并能逐条自证完成。

## 改了什么
- **验收标准重写**：每条都写成可直接验证的形式（命令、接口返回、页面行为、数据条件），覆盖正常、异常、边界；错误码与《接口规范》§1 / §3 对齐。规范里没有的错误码（如 413 FILE_TOO_LARGE、415 UNSUPPORTED_TYPE、URL_NOT_ALLOWED、PARSE_FAILED）在验收里要求同步写进规范。
- **纠正与规范不一致**：#13 原写「删最后一个管理员返回 409 LAST_ADMIN」，规范 §3.9 为 `400 LAST_ADMIN`，已更正。
- **新增「写入范围」小节**：每个未开工的 Issue 写明只改哪些文件 / 目录，同批任务互不重叠（例如 #3 的 CI 通过 `npm --prefix web run test:smoke` 接 #4 的冒烟，#4 不改 workflow；#47 用自己的 `deploy/mock-gov/Makefile`，不和 #11 抢根 Makefile）。
- **新增「建议拆分（jk-squad）」小节**：10 个偏大的 Issue 写明小组内怎么分 worker。
- **已被 HA worker 领取的 Issue**（#2 #3 #5 #6 #7 #8 #50 #51）：范围不动，只在原验收后追加「补充验收（第二版）」，并在 Issue 下评论说明。
