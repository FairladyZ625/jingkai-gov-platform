# 企业服务工作台（#226）

企业服务围绕一份企业档案持续开展。工作台提供工作概览、企业档案、联系与走访、诉求看板四个入口，原四个应用的入口及顺序保留。原应用与工作台读取、修改同一套企业接口；本机演示也复用原有 mock 数据，没有另建工作台业务库。

## 使用路径

- 概览统计可以直接进入对应筛选结果。逾期指北京时间当前日期之前到期、尚未办结的诉求；未设置期限不计为逾期。
- 档案页支持查询、新增和编辑基本资料，并直接查看联系人、联系记录和关联诉求。字段按服务器已授权返回的值展示，不能从浏览器反推被脱敏的信息。
- 联系与走访可以直接登记电话、线上沟通、上门走访或会议座谈，不必每次经过原来的四步流程。整理出的档案更新建议仍须逐条人工确认。
- 诉求独立于某次走访长期办理。看板包含待分派、办理中、待补材料、已办结；经办人可以修改负责人、期限、下一步安排并填写本次进展。实际变化及操作者进入原办理时间线。
- 新登记诉求未填写负责人时进入待分派。原接口调用省略负责人仍保持原默认行为；显式空字符串表示不分派。

## 一致性与权限

路由只保存当前视图、记录 ID 和筛选条件，业务记录每次从 `JKApi.enterprise` 读取。刷新页面恢复原视图，切换模块或身份后旧请求不能重绘当前工作台。

工作台写入成功会使已打开的原企业应用缓存失效；重新打开应用或从工作台返回对话时，原应用读回最新资料、诉求及档案。失败显示可读原因，读取失败可重试；空数据不生成虚构统计。

工作台沿用企业应用的 view/operate 权限。只读身份不显示写入口，HTTP 和 mock 接口继续负责最终鉴权；旧企业详情返回的诉求也使用同一脱敏投影，联系记录正文、附件和历史不向原本无权身份开放。负责人是原业务记录中的文本字段，不赋予账号权限。

## 验证入口

```sh
python3 -m pytest -q apps/enterprise/tests
node --test web/tests/contract/enterprise-issues.test.cjs
node --test web/tests/workbenches/enterprise-browser.cjs
```

真实 Chromium 浏览器覆盖新增企业→电话联系→登记诉求→分派及跟进→刷新恢复→旧应用读取的完整流程，另覆盖统计筛选、读取失败及重试、只读身份、空记录、同页连续编辑/联系、HTTP 兼容联系人字段以及返回对话后的缓存刷新。1440、1280 和 390 像素视口检查布局；截图存于 `docs/screenshots/enterprise-workbench/`。这些浏览器用例使用离线演示数据；HTTP 业务规则由应用 TestClient 测试独立验证，不代表生产环境验收。

会议来源回链在 #227 集成，不在本单新增重复诉求数据或未实现接口。跨部门正式派单、自动审批、企业外部登录入口不在本次范围。
