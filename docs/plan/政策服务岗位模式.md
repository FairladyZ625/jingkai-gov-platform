# 政策服务岗位模式（#229）

在现有对话输入区选择“通用助手”或“政策服务专员”，保留四个应用的入口和位置。政策服务可选择当前账号有权查看的企业，也可以先不指定企业、直接咨询政策。选择岗位不增加任何权限，不建立企业外部门户。

## 实际行为

政策岗位每次先调用已有只读 `policy.search` 工具。它查找当前已经收录的政策支持，按政策名称、编号和具体主题词定位依据，返回申请条件、材料、期限及原文，再提示经办人还需确认什么。企业名称、行业和规模只从当前账号可读的企业台账取得，用于明确服务对象，不能据此推断已满足所有申请条件。

每一轮先查询当前问题。明确换了编号或主题时使用本轮查询；只有“那需要什么材料”等缺少独立主题的指代追问，才在首次查询提示澄清后继续查询上一轮的主题。每次实际调用都保留在工具记录中。没有原文、查询失败、企业不可读取时分别明确说明，不能用旧引用填补陌生题材。历史政策保留原目录的历史状态和申报时间说明。

第一版采用确定性目录检索和依据回复，不调用语言模型自由生成政策事实。原文中的要求仍需结合企业实际情况人工核对；系统不自动认定资格、承诺获批、申报或审批。需要写入、起草、送审时仍使用原应用的明确操作入口。

## 上下文与旧入口

- 岗位和企业保存在当前会话，刷新后打开该会话可恢复。新会话、换账号和切回通用助手清空企业选择。
- 升级前没有岗位字段的旧会话默认通用助手，不继承首页未发送草稿的企业。
- 消息发送时固定它自己的岗位和企业。请求等待期间切换企业不改变已发出消息的上下文。
- 服务端只把连续相同岗位、相同企业的消息用于追问；会话所属账号仍由原所有权校验负责。
- HTTP 请求新增可选 `mode: general | policy_service` 和 `enterpriseId`；旧调用不传模式时仍走通用编排。非法模式拒绝，政策岗位要求原政策查询权限。
- `policy.search` 新增可选 `queryMode: question` 与 `enterpriseId`。不带这些参数的原政策目录子串检索保持兼容。

离线模式使用同一演示政策查询接口和权限边界，并按新会话的所属账号隔离。对于没有可确认所属账号的旧离线服务会话，政策岗位会提示新建会话，不把旧记录直接归给当前账号。

## 页面表述

政策应用说明改为“根据企业信息，查找可能适用的政策支持，查看申请条件和原文依据。”；首步明确当前目录已收录多少项政策支持，不再把目录总数表述为企业必须核对的条件数。每项结果代表政策提供的一种支持，不是已与企业发生的事件。

最终结果称“政策参考清单”。旧 `policy.notice` 工具及接口名称保留，“告知单”旧问法继续识别；展示、下载文件名、输出标题使用新名称。对话引用打开对应政策条款及原文，而不是误跳到无关知识库文件。
