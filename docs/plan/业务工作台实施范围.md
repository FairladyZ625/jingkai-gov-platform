# 业务工作台实施范围

关联 #224、#225。用户已授权新增企业服务、会议纪要、公文协作三个工作台和政策服务岗位模式；政策岗位由独立任务实施。本单先交付共同入口。

- 主导航保留四个业务应用的现有顺序，另设工作台一级板块。入口同时遵守对应应用的启用状态与 `view` 授权。
- 工作台占用主内容区域；`#/workbench/<id>?record=<id>` 保存模块和记录上下文。各工作台在同一登录身份内记住最近记录，支持刷新和浏览器前进后退。换账号或退出时清除上下文，旧账号的历史记录链接不会自动恢复。对话记录仍由原对话机制维护。
- 后续模块调用 `JKWorkbench.register(id, { mount(el, ctx) })`。`ctx` 包含 `userId`、`appId`、`recordId`、对应的既有 `JKApi` 适配器、`can(action)` 和 `open(recordId)`。模块通过该适配器访问原业务记录，不建立第二份业务数据；写操作仍由原 API 鉴权。`mount` 可返回 `{ unmount() }`，离开工作台或切换记录时释放订阅和请求；已卸载模块的导航回调失效。
- 未注册模块显示“正在准备”及现有应用入口，挂载错误显示明确错误。工作台的具体首页、列表、详情和写操作分别由后续三个 Issue 实现。
- 会议设计详见同目录《会议纪要工作台设计草案》。

## 分步交付

- #225：本单，共用导航、挂载机制与回归保护。
- #226：企业服务工作台，企业档案、联系与走访记录、诉求看板及跟进。
- #227：会议纪要工作台，材料与纪要核对、经办人确认定稿、待办和原文依据；正式审签转公文协作。
- #228：公文协作工作台，草稿、退回修改、待我审签、定稿档案与既有版本/评论/导出衔接。
- #229：政策服务专员岗位模式，先查政策、结合企业诉求答复并保留原文依据；原四个应用的分级与位置保留。

本单不把工作台占位入口视为业务功能完成。后续模块须以实际业务记录和可走通的办理流程验收。
