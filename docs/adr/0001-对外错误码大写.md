# ADR 0001　对外错误码统一使用大写 SNAKE_CASE

Issue #130 将公开 HTTP 和 SDK mock 响应中的平台保留码统一为大写 SNAKE_CASE。应用自定义错误码按登记时的原拼写返回，已有小写码继续有效。core 根据 `DataError` 的平台分类及调度、长任务使用的额外平台码判别，jobs 在读取快照时转换已知平台码，历史存储无需迁移。经开区 v1 兼容层沿用同一分类，并保留认证别名和既有错误信封。

平台应用目录 `GET /api/apps` 返回清单的 `sdk` 字段，旧清单缺省为 `"1"`。外壳把目录项传给 `createContext`。SDK 1 的应用请求及绑定的资源句柄恢复旧平台码字面量，因此旧模板的 `version_conflict` 分支仍能读取最新版本并提示用户再次保存。SDK 2 应用收到大写平台码。应用上下文以外的顶层 `http`、`v1`、直接 HTTP 和自行打包的旧客户端都遵循公开传输契约，逐字比较平台码的消费者需要适配。Python 和 JavaScript 的公共包版本保留为 2.0.0，Python SDK 内部异常码和审计动作沿用原语义。

HTTP 状态、消息、错误详情和重试语义沿用原约定。core 和 jobs 保留直接返回的 `retryable`。经开区 v1 信封将可重试标记带入 `error.details.retryable`，缺省表示没有可重试提示。

`tests/compat/sdk1-surface.json` 保留冻结原件，并校验其摘要及仍受支持的签名和资源句柄。`tests/compat/sdk2-surface.json` 单列校验当前包版本、签名和公开 HTTP 样例。冻结应用继续验证真实平台行为，旧模板回归另用 Node 调用真实 HTTP，检查两种 SDK 1 清单的 409 重读和二次保存、SDK 2 的大写码及顶层 mock 传输。core 和经开区的 HTTP 测试分别验证平台码与应用自定义码，jobs 用例覆盖持久化记录读出。
