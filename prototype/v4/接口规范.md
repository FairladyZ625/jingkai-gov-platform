## 1. 通用约定

| 项 | 约定 |
|---|---|
| 协议 | HTTPS + JSON（UTF-8）；文件上传 `multipart/form-data`；对话流式 `text/event-stream`（SSE） |
| 认证 | 会话 Cookie（卫华 `auth.py`，`credentials: same-origin`）；后续可接 OIDC / 政务统一身份。服务间调用 `Authorization: Bearer <token>` |
| 权限 | 服务端判定：用户角色 × 应用 × 动作（`view / operate / approve / admin`，卫华 `rbac.py`）；资料按库 × 角色可见；外部协作者字段级脱敏 |
| 分页 | `?limit=50&offset=0`，响应 `{ items:[], total }` |
| 时间 | ISO 8601，北京时间；展示层转“2026年11月17日” |
| 错误 | HTTP 状态码 + `{ "error": { "code": "CHECK_FAILED", "message": "还有 1 处必须修改的问题", "details": {} } }`（卫华 `DataError` 格式） |
| 留痕 | 所有写操作、模型调用、导出写审计：`[时间, 用户, 应用, 动作, 模型]` |
| 幂等 | 写接口支持 `Idempotency-Key` 头（长任务、导出） |

对外接口（含应用健康检查）的 `error.code` 一律使用大写 SNAKE_CASE。部分既有 SDK 和健康检查响应的大小写仍待 #130 对齐。

## 3. 平台接口 `/api/v1`

### 3.1 账号登录与个人（复用卫华 auth / identity / passwords）
| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/auth/login` | `{username,password}` → `{ user, role, grants }` 并设置会话 Cookie；口令错误（含停用账号）返回 `401 BAD_CREDENTIALS`，停用账号口令正确返回 `403 ACCOUNT_DISABLED`。第 5 次连续输错仍返回 401，并锁定 10 分钟；锁定期内再次登录返回 `409 LOCKED`，`details.retryAt` 是北京时间 ISO 8601。成功登录清零计数 |
| POST | `/api/v1/auth/logout` | 清除会话，写审计 |
| GET | `/api/v1/auth/session` | → `{ user|null }`，前端启动时判断是否已登录 |
| GET | `/api/v1/me` | → `{ user, role, org:{id,name,seats,used}, settings, grants }`，前端据此隐藏无权应用、决定按钮可用 |
| PUT | `/api/v1/me/password` | `{old,new}`；原密码错 `400 BAD_PASSWORD`，新密码少于 6 位 `400 WEAK_PASSWORD` |
| PATCH | `/api/v1/me/prefs` | `{ theme?, defaultModel?, operatorEnabled? }` 个人设置（含“替我操作”开关） |
| PUT | `/api/v1/me/role` | 仅演示环境（`JKQ_DEMO_MODE=1`）：`{role}` 允许已登录的演示账号切换视角 → `{ user, role, grants }`；正式环境即使匿名或请求体无效也返回 `404 NOT_FOUND` |

部门管理的兼容路径在当前实例返回 `404 NOT_FOUND`（接口待接入）。

**权限判定规则**（服务端，每个接口都执行，前端隐藏只是体验）：`allow = grants[role][app] ∪ grants[role]['*']` 包含所需动作。读接口要 `view`，写接口要 `operate`，审签/确认入库要 `approve`，`/api/v1/admin/*` 要 `admin`；越权一律 `403 FORBIDDEN { details:{app, need} }` 并写审计。外部协作者（`role.mask=true`）读取企业数据时，服务端按 `MaskRule` 打码后再返回，导出同样打码。

### 3.2 模型网关（多模型统一接入）
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/models` | → `{ items: Model[], current, capabilities }` |
| PUT | `/api/v1/models/current` | `{model}` 切换个人默认模型；海外模型未开放 → 403 `MODEL_DISABLED` |
| PATCH | `/api/v1/models/{id}` | 管理员启停 `{enabled}` |
| POST | `/api/v1/ai/chat` | 网关直连（无应用编排）。请求见下 |
| POST | `/api/v1/ai/transcribe` · `/embedding` · `/parse` · `/vision` · `/search` | 卫华 aihub 已有能力（原型不直接调） |

### 3.3 对话

原型在本地对话记录保存 `Conversation.panel = { app, route, params }`。`app` 为已注册的应用 ID，`route` 为应用路由，`params` 为可序列化的导航参数对象，首页使用 `'home'` 和 `{}`。切换到历史对话时，外壳按该记录恢复面板。没有 `panel` 的旧记录和新对话均显示空面板，再打开应用时从首页开始。首次打开应用时先等待它提供的可选 `ready()`，3 秒内未完成则显示首页并记录一条控制台警告。政策试算快照可带 `params.calcAmounts`，键为事项 ID，值为手填金额（元），清空记为 null。旧快照缺少该字段时沿用台账，恢复后调用试算接口重新计算。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/conversations` | 当前用户未删除会话，按 updated、id 倒序。limit 默认 50、offset 默认 0，均为 0 至 9223372036854775807 的整数 → `{items,total}` |
| POST | `/api/v1/conversations` | `{title?, app?, panel?}` → `{item}` |
| GET | `/api/v1/conversations/{id}` | → `{item, messages}`，消息按写入顺序排列 |
| PATCH | `/api/v1/conversations/{id}` | `{panel}` → `{item}`，传 null 清空面板 |
| DELETE | `/api/v1/conversations/{id}` | 软删除，返回 204 空响应。消息与面板保留 |
| POST | `/api/v1/conversations/{id}/restore` | 无需请求体，无撤销时限，成功返回 200 `{item}`。仅可恢复本人已删除的会话 |
| POST | `/api/v1/conversations/{id}/messages` | 发消息，编排：意图识别 → 调小应用工具 → 生成回复 + 卡片 |

会话时间使用北京时间 ISO 8601。详情、面板更新和删除对他人、不存在或已删除的会话均返回 404，恢复目标不符合条件也返回 404。匿名请求返回 401。非法分页或请求字段返回 `422 CHECK_FAILED`；文本及面板参数的键值须能编码为 UTF-8，数值须有限，校验失败保留原记录。

```jsonc
{ "text": "书香里文化能申请哪些支持？", "model": "deepseek-v4-pro", "app": null, "files": [] }
// 200
{ "conversation": {"id":"C-301","title":"书香里文化能申请哪些支持","app":"policy","updated":"刚刚"},
  "user":  {"id":"M-201","role":"user","content":"书香里文化能申请哪些支持？"},
  "reply": {"id":"M-202","role":"assistant","model":"Qwen3-32B（本地）",
            "routeNote":"涉及企业台账（内部数据），已从 DeepSeek-V4-Pro 切换到本地模型，数据不出局",
            "intent":"policy","toolCalls":[{"tool":"policy.match","args":{"entId":"E001"}}],
            "content":"已按「书香里文化」的台账画像…**2 项可进一步核对**…",
            "cards":[{"type":"policy-match","entId":"E001","results":[{"id":"PI-03","title":"实体书店成本奖励","level":"ok","calc":{"amount":200000}}]}],
```

`app` 传值 = 用户用 “/” 指定了应用，跳过意图识别。

**对话附件（拖文件 / 贴链接 / 贴文本）**：对话框接收到文件或链接后，先识别类型，再同时给出“打开哪个应用、是否入库”。置信度不足时操作员用 `mode:'confirm'` 询问“我理解为…，要这样做吗？”。

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/conversations/{id}/attachments` | `multipart`（`files[]`，可附 `url` / `text` / `lib?`）→ `{ items: Attachment[], routes: RouteHint[], job? }` |
| GET | `/api/v1/conversations/{id}/attachments` | 本对话已附文件 `{items}` |
| GET | `/api/v1/conversations/{id}/attachments/{attachmentId}/content` | 下载原文件，Content-Disposition 的 filename* 使用 UTF-8 |

单次上传的文件字节与链接、文本的 UTF-8 字节合计最多 10 MiB（含 10,485,760 字节）；multipart 传输另留 64 KiB，最多 16 个文件、3 个普通字段。支持 mp3、m4a、wav、aac、ogg、flac、mp4、webm、pdf、doc、docx、wps、txt、md、xls、xlsx、csv、jpg、jpeg、png。超出字节限制返回 413，类型不支持返回 415，表单数量超限返回 422。无法归类的附件返回 `mode: "confirm"`、`action: "ask"`。

分流约定（也可写在各应用 manifest.`accepts` 里，见 §5；外壳按文件名、类型和前 4KB 文本打分）：

| 识别为 | `kind` | 默认 `routes` |
|---|---|---|
| 政策 PDF、带文号的公文、经开区 / 首都之窗政策链接 | `policy` | 入库 `lib:'policy'`，打开 `policy` |
| 录音 / 会议视频 | `audio` | 打开 `meeting`（可同时入库 `meeting`） |
| 走访笔记、企业材料 | `visit` | 打开 `enterprise`（`tab:'visit'`） |
| 通知、函件、文稿 | `document` | 打开 `document` |
| 无法判断 | `unknown` | 只询问；用户也可选择“仅入库” |

写操作（入库发布、打开后直接提交）仍然要按 §3.8 在 `write:true` 步骤停下确认。

| 方法 | 路径 | 说明 |
|---|---|---|
| PUT | `/api/v1/kb/messages/{messageId}/citations` | 以 `{citations:[{fileId,snippet}]}` 按显示顺序替换本人消息的引用。两字段均为字符串，未指定版本时固定到写入时的现行版本 → `{ok:true}` |

内容完全相同会跳过；同文号或标题高度相似可“作为新版本”。`confidential` 内容不得送出域模型。

```json
      { "id": "s3", "label": "填入走访记录", "action": "type", "target": "vs-notes", "value": "…", "write": false },

      { "id": "s5", "label": "写入台账（需要你确认）", "action": "confirm", "tool": "enterprise.proposal_decision", "write": true } ] }
```
规则：
- `mode`：置信度 ≥ 0.75 → `execute`；0.4–0.75 → `confirm`（回复“我理解为…，要这样做吗？”，用户点“是”再执行）；低于 0.4 → `answer`（普通对话回答）；缺权限 → `forbidden`（说明缺哪个应用的什么权限、找谁开通）。
- `write=true` 的步骤（写入台账、送审签、审签通过、派发待办、改授权）**永远停下来等用户点确认**，AI 不会自己提交。
- 每一步都走与界面相同的接口与权限判定；`call` 步骤等价于 `POST /api/v1/apps/{app}/tools/{tool}`。

### 5.3 操作员钩子（`actions` + `run`）

外壳理解用户的话（关键词 + 模糊 + 实体抽取），在对话里展示任务计划并逐条打勾，再调用 `actions[action](slots, run)`。操作员要点的元素必须带 `data-op="<appId>.<name>"`，不要依赖 class 名。

`run` API：`step(i)`、`fill(sel, text)`、`click(sel)`、`select(sel, value)`、`highlight(sel, note?)`、`scroll(sel)`、`wait(fnOrSel, timeout)`、`sleep(ms)`、`ask(question, options)` → 用户所选（**签发、提交、入库、删除、对外发送、电脑操作提交/登录/签字前必须 `ask`**；演示模式自动选第一项）、`say(text)`、`done(summary, nextActions)`、`fail(msg)`、`stopped`（用户点停止后为 true，动作应尽快返回）。

`run.ask` / `run` 的确认步骤与 HTTP 层 `OperatorStep.write=true`、`POST /api/v1/operator/runs` 同时记账。钩子只负责高亮和等待，不得自行提交。

| `computer` | `run`（“帮我去…系统填/登录…”；提交/登录/签字前必须 `run.ask`） |
| `kb` | `import` · `ask` · `open` |

文件投递：外壳统一接收（拖到对话区、粘贴、回形针、或 `config/sample-files.js` 样例），按各应用 `accepts` 打分，打开最匹配的应用并调用 `actions.intake({ file }, run)`。识别不出时给出 2–3 个选项（必须包含“存入知识库”）。`file = { name, ext, size, kind, text, dataUrl?, sample? }`。音频/图片不读文本，只给 `kind`。HTTP 层对应 `POST /api/v1/conversations/{id}/attachments`（§3.3）。

### 5.4 事件

外壳与应用通过 `ctx.bus.emit` / `ctx.bus.on` 通信，不互相读取内部 DOM 或 localStorage。共享数据只走 `ctx.api` 与 `ctx.kb`。

| 事件 | 由谁发出 | 谁关心 |
|---|---|---|
| `kb:changed` / `kb:updated` | 知识库 | 原文抽屉、引用角标、对话出处 |
| `todo:changed` / `inbox:changed` | 应用在写入 `/api/v1/todos` 或 `/reviews` 后 | 收件箱角标 |
| `data:reset` | 外壳（重置演示数据） | 所有应用回到初始状态 |
| `app:ready` / `app:opened` / `app:state` | 应用或外壳 | 操作员开始执行、深链落到对应步骤 |
| `job:progress` | 平台 | 会议转写、知识库解析 |
| `review:needed` | 应用 | 收件箱 |
| `operator:step` / `operator:stop` | 操作员 | 对话里的任务计划打勾 |

### 5.5 两种扩展方式

## 6. 适配层与模拟后端（综合版，契约 1.1）

界面代码禁止访问 `window.JK_DATA` / `JKAPI` / `MOCK`。只调 `ctx.api.<模块>.<函数>()`（即 `window.JKApi`），由 `api/http.js` 统一出口：

```
界面 apps/<id>  ──只调──▶  api/<id>.js（入参→出参与本规范同名同构）
                               │  JKHttp.request(method, path, body)
                               ▼
         JK_CONFIG.api.mode = 'mock'  →  mock/mock-api.js + mock/<id>.js
                            = 'http'  →  fetch(baseUrl + path)（真实后端，界面一行不改）
```

开关在 `config/app.config.js`：`api: { mode: 'mock', baseUrl: 'http://127.0.0.1:8080', timeoutMs: 20000 }`。`mount` 可返回 `ready: () => Promise`，外壳打开应用后先 `await ctl.ready()` 再调用 action。

综合版入口 `v4/index.html`（`file://` 可打开）。政策与知识库种子来自经开区官网公开文件（92 份政策、83 条真实条款、189+ 篇文档），见 `v4/data/REAL_DATA.md`。AI 的生成结果在 mock 模式下为模拟。

```js
await ctx.api.enterprise.list({ q: '星河' });
await ctx.api.policy.match({ entId: 'E002' });
await ctx.api.kb.ask({ q: '数据券补贴最高能拿多少？' });
await ctx.api.kb.importNow({ url: 'https://kfqgw.beijing.gov.cn/zwgkkfq/2024zcwj/202507/t20250715_4150108.html', space: 'policy' });
await ctx.api.computer.start({ task: 'apply', ent: 'E002' });
await ctx.api.computer.confirm(runId, { decision: 'approve', kind: 'submit' });
await ctx.api.skills.draft({ text: '核对数据券申报材料齐不齐' });
```

状态持久化在浏览器 localStorage（独立键，避免与旧三版串数据）；头像菜单“重置演示数据”调用 `POST /api/v1/demo/reset`（mock 模式在本地重置）。一键演示脚本见 `config/demo-script.js`（12 段，默认 `demoSpeed: 1.6`，实测约 3 分钟）。
