# v4 综合版 · 四个小应用合并方案（apps worker）

> 依据：`shared/requirements.md` §2–§5、v1/v2/v3 源码与无头浏览器演示截图（`/workspace/jk/v4test/sheet-*.jpg`）。
> 总原则（Rick t9u/t14u）：**一屏一件事、字少、重点大**；v2 的分步向导做骨架；v3 的“结果可编辑 + 版本 + 比对 + 导出”做公文；v1 的“data-demo 锚点 + go(view,args) 深链”做 AI 操作接口；颜色只用 DESIGN.md 的语义 token 和标签色板，每个应用一个身份色。
> 数据：优先用 `v4/data/` 的经开区**真实公开政策**（REAL_DATA.md，带原文链接）；没有出处的标“示例”。检索/引用一律走 `ctx.kb.search / ctx.kb.ask`，应用里不自建检索。

## 0. 三版对比结论（应用层）

| | v1 对话+右侧面板 | v2 工作台+4 步向导 | v3 对话+画布 |
|---|---|---|---|
| 应用骨架 | 页签（匹配/事项库/试算），流程靠用户自己找 | **固定 4 步条 + 上一步/下一步 + 底部主按钮**，小白最好懂 | 结果“画布”，可编辑、存版本、比对、分享、导出 |
| 信息密度 | 偏高，卡片里 chip 太多 | 适中，但每步顶部说明文字偏长 | 偏高，工具页签多 |
| AI 操作接口 | **`data-demo` 锚点 + `go(view,args)` 返回句柄**，最干净 | `JK.policyW={W,st,select,runMatch}` 暴露内部状态，耦合 | 画布 artifact，渲染器与 agent 耦合 |
| 独有亮点 | 额度试算“常见问法”一键代入；企业不在台账手动画像；⌘K | 原值→新值→**原话依据**；AI 30 秒速览；语音输入；派发前强制补齐；“用示例填好” | 公文**版本时间线/回到此版本/比对 +x −y 字**、定稿锁定、导出 Word、“正在看第 N 版”；会议波形回听条；台账提醒三卡 |
| 丢弃 | 页签式主流程、chip 堆叠 | 每步大段说明、助手侧栏挤压内容 | 画布外壳本身（v4 用 v1 右侧面板挂载） |

**统一骨架（四个应用相同）**：
```
┌ 应用头：身份色图标 · 应用名 · 一句话（≤16 字）· [问 AI] [辅助视图▾] ┐
├ 步骤条 ①②③④（可点回已完成步骤；当前步高亮身份色）              ┤
├ 本步内容：只放 1 个核心对象 + 1 个结论数字/状态（大号）            ┤
│   次要信息折叠在“详情 / 原文 / 高级”里                              │
└ 底栏：[上一步]                       [次按钮]  [主按钮 · 唯一]     ┘
```
辅助视图（事项库、台账、诉求看板、全部会议、我的文稿…）放在头部“更多”切换，不进主流程。

## 1. 政策兑现咨询 `policy`（身份色：DESIGN.md `--app-policy`）

**各版最好**：v2 的 4 步（选对象→核对→试算→告知单）+ 信息不全标“待确认”不判否；v1 的试算预设问法 + 手动画像；v3 的“补数字立即重算”就地输入 + 告知单可编辑。
**保留**：三分组（可核对/待确认/不满足）用 3 个大数字做结论；条件 ✓ ? ✗ 清单；三个时间（有效期/发生期/申报窗口）+ 窗口徽标；看原文抽屉（`ctx.kb` 取原文段落 + 文号 + **官网链接** + 核验日期）；版本提示（同名多版本）；跨事项限制；主体角色。
**丢弃**：结果卡片里的 6–8 个 chip（只留 窗口状态 + 封顶额度 两个）；每步长说明。
**最终流程**：
1. **选对象**：搜企业（名称/简称/信用代码）→ 画像卡（≤4 个关键标签）；或“手动描述”（对象类型/标签/年限/金额）。主按钮「开始核对」。
2. **核对条件**：顶部一句结论 + 3 个大数字；待确认卡片内直接补缺项（“填入示例”）→ 自动重算；每项「看原文」。主按钮「试算额度」。
3. **试算**：已选事项逐项“金额 × 比例 → 封顶”，大号显示合计；保留“最高/不超过/经评审”。主按钮「生成告知单」。
4. **告知单**：可编辑文本（带“仅供参考，以正式申报审核为准”）；主按钮「复制」，次：下载 / 转为公文答复（→document T10）/ 记入企业诉求（→enterprise issues）/ 存为技能。
辅助视图：事项库（对象/窗口筛选 + 口语扩展词搜）、政策文件（真实文件列表 + 链接）。
**AI 可驱动**：`select(entId|profile)`、`match()`、`fill(field,value)`、`calc(itemId,amount)`、`notice(ids)`、`openSource(itemId)`、`toDocument()`、`logIssue()`、`view('items',{q,obj,win})`。
**RBAC**：外部协作者只看已发布事项、画像不显示营收（mask）；无 operate 不能“记入企业诉求”。

## 2. 企业管理维护 `enterprise`（身份色 `--app-enterprise`）

**各版最好**：v2 的 4 步（找企业→一企一档→记走访→跟诉求）+ 原值→新值→原话依据 + 语音输入 + 全部采纳；v3 的顶部提醒三卡（资质临期/久未走访/诉求临期）+ 台账筛选；v1 的 30 秒摘要卡 + CSV 导出。
**保留**：字段核验状态（自报/已核实/预测，用标签色）；信用代码+曾用名防重名；变更历史；服务关系；诉求看板 4 列；新建企业/导入 Excel（字段映射预览）。
**丢弃**：一企一档 6 个页签全铺开 → 改为 3 块（概况 / 经营与资质 / 走访与诉求），联系人与原始资料折叠。
**最终流程**：
1. **找企业**：3 张提醒卡（数字大）+ 搜索；点卡片即筛选。
2. **一企一档**：顶部 AI 30 秒速览（4 行）；下方 3 块档案。主按钮「记一次走访」，次：能申请哪些政策（→policy）、起草答复（→document）。
3. **记走访**：输入/语音/「填入示例」→「整理」→ 建议列表（旧值 → 新值 · 原话依据）逐条 确认/改/忽略 + 新诉求一键登记。**AI 不直接写台账**，主按钮「确认写入 N 条」（人把关点）。
4. **跟诉求**：时间线 + 改状态/责任人/写进展；看板视图。
辅助视图：台账列表（筛选/排序/勾选导出 CSV/导入）、诉求看板。
**AI 可驱动**：`find(q|filter)`、`open(entId)`、`brief()`、`visit(text|'sample')`、`organize()`、`decide(proposalId,'accept'|'ignore')`（停在“确认写入”前等人）、`issue(id,{status,note})`、`filter({tag,alert})`、`export()`。
**RBAC/脱敏**：外部协作者电话、营收打码，写入按钮隐藏；接口层 403 时显示错误态。

## 3. 会议记录 `meeting`（身份色 `--app-meeting`）

**各版最好**：v2 的 4 步（选录音→自动整理→核对转写→纪要与待办）；v3 的长任务 5 步进度卡 + 波形回听条 + 完成后可离开；v1 的逐字稿表格（时间戳/发言人/听不清高亮）+ 发言人全篇改名。
**保留**：录音来源三种（NAS 新到 / 上传 / 现场录音计时）；模板三套；热词；“各方意见 vs 议定事项”分开；待办缺责任人/期限标黄，补齐才能派发；关联企业诉求；可见范围标签（仅局方）。
**最终流程**：
1. **选录音**：NAS 新到列表（1 个主卡“整理这份”）+ 上传/现场录音；设置（模板、参会人、热词）折叠。
2. **自动整理**：5 步进度（上传校验→本地转写→区分发言人→热词纠错→生成纪要待办），可「离开，完成后通知」。
3. **核对转写**：逐字稿 + 回听条；[听不清] 高亮可点改；点发言人改名。
4. **纪要与待办**：纪要（按模板，可编辑，段落带回听时间戳）+ 待办表；主按钮「派发选中」，次：转为公文（→document T02，带议定事项）、关联企业诉求、导出 Word。
辅助视图：全部会议、待办总览。
**AI 可驱动**：`pick(meetingId|'nas-latest')`、`start({template})`、`seek(ts)`、`rename(from,to)`、`fixTodo(i,{owner,due})`、`dispatch()`、`toDocument()`、`linkIssue(entId)`、`export()`。

## 4. 公文协作 `document`（身份色 `--app-document`）

**各版最好**：v2 的 4 步（要办什么事→填要素→初稿与核查→批注与送审）+“用示例填好”；**v3 的版本时间线、回到此版本、版本比对（+x/−y 字高亮）、定稿锁定、导出 Word**；v1 的红头稿纸（两种主题都白纸）+ 点段落直接改。
**保留**：10 类场景卡分三组（写“什么时候用”）；缺项写【待补：xxx】；核查（必须改/建议改/提示 三色）+ 一键修正；润色先看对比再采用；批注回复解决；送审签拦截；审签人通过/退回；定稿锁定 409；未定稿导出带水印；范文参考走 `ctx.kb.search({lib:'公文范本'})`、政策依据从真实政策选。
**最终流程**：
1. **要办什么事**：10 张场景卡（3 组），每卡 1 行用途。
2. **填要素**：3–4 个字段已预填 +「用示例填好」+ 勾引用资料（纪要/范文/政策原文）。主按钮「出初稿」。
3. **初稿与核查**：左稿纸，右侧工具只 3 个页签：**核查 / 润色 / 版本**（比对放在“版本”里：选两版 → 高亮）。主按钮「全部一键修正」。
4. **批注与送审**：段落批注、未解决数；主按钮「送审签」（人把关点）；审签人视角：通过定稿（自动补文号）/ 退回；「导出 Word」。
辅助视图：我的文稿、通用润色/比对工具（粘贴任意两段）。
**AI 可驱动**：`template(id)`、`fill(inputs|'sample')`、`draft()`、`check()`、`fixAll()`、`polish(style,para?)`、`adopt()`、`compare(vA,vB)`、`restore(v)`、`comment(para,text)`、`submit()`（停在送审前确认）、`approve()/reject(reason)`（仅审签人）、`exportWord()`。

## 5. 跨应用一致规则
- **标签颜色**：只用 DESIGN.md 的语义映射（例：窗口 申报中/本批已结束/待通知；结论 可核对/待确认/不满足；核验 已核实/自报/预测；诉求状态 4 种；核查级别 3 种；公文状态 草稿/审签中/已定稿/退回）。同一含义全站同色。
- **字数**：应用头说明 ≤16 字；每步提示 ≤1 行；长说明进“？”气泡。
- **状态**：每个列表/结果区都有 空状态（引导 + 一键示例）、加载骨架、错误态（403 无权限 / 404 / 409 锁定 / 网络），文案配置化。
- **配置**：步骤名、按钮文案、示例、预设问法放 `apps/<id>/config.js`，不进代码。
- **人把关点（3 处）**：台账写入、公文送审/定稿、技能上架（不在本 worker）。AI 操作到这里停下高亮按钮等人点。
- **深链**：policy→document(T10)、policy→enterprise(issue)、enterprise→policy、enterprise→document、meeting→document(T02)、meeting→enterprise(issue)。
