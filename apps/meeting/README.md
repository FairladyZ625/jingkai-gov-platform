# 会议纪要与待办

### 1. 触发

录音转写完成后，打开会议详情核对纪要和待办。

### 2. 使用者与确认人

具备会议查看权限且能访问所属项目的成员可阅读逐字稿及纪要。经办人有操作权限，可更正内容、派发待办、登记企业诉求。派发时负责人须能查看来源会议。

### 3. 输入

使用转写任务保存的逐字稿，每行包含时间戳、发言人和原文。经办人补充待办负责人和期限。登记诉求时提供企业 ID，可选填诉求标题。

### 4. 处理步骤

1. 按逐字稿提取明确的议定语句与待办，缺乏明示结论时显示发言摘录。
2. 经办人核对发言人、逐字稿及纪要。逐字稿修改后，引用该行的已编辑段落标记待复核。
3. 派发时逐条校验待办，成功的分派与会议记录通过同一次版本写入持久化。
4. 企业诉求写入企业应用。起草公文时返回公文模板、预填内容和会议来源。

### 5. 确认依据

以当前逐字稿的时间戳和原句核对结论。派发前核对事项、唯一的在用负责人和期限。会议待办的派发结果可按接收人查询。

### 6. 输出

会议详情返回逐字稿、带引用的纪要和待办。派发接口返回成功 ID 和跳过原因。个人待办通过 `GET /api/apps/meeting/my-todos` 读取。企业关联返回新诉求，公文接口返回导航参数。

### 7. 验收样本

`tests/test_meeting_workflow.py` 使用公开演示语句和隔离会话覆盖编辑、派发、权限、企业接口及转公文参数。企业诉求测试使用 §4.2 契约夹具。
